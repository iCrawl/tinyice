Accepted minimal implementation contract

1. Stream owns the exclusive source generation and closer. A claim is acquired before BeginSession, configuration, Opus header construction, registry attachment, or Broadcast. Claim identity includes stream identity and generation; labels are diagnostic values and never ownership keys. Migrate all actual byte-producing paths, including transcoder outputs, rather than leaving a second permissive label-based claiming API. Existing public transport entry points remain. Writer cancellation and completion precede release; detach, closer cleanup and removal compare identity. Browser replacement waits for both old audio/video pumps, rejecting timeout. This adds a narrow capability to existing locks; it does not require a generic source framework.

2. Registry owns only detached mount/source/output facts, not streams or publication rights. Reads copy nested output collections and source values. Detach only the matching source; HLS attachment persists independently across flaps and is removed on actual output removal. Tenant active-source counts derive from these records. Avoid a separate cache of the same ownership facts.

3. One AutoDJ lifetime owns its persistent encoder pump and one playback loop selects tracks and handles recovery. Validate a first playable track before opening its claimed session. Normalize through exactly one gain stage, one rate conversion and an outer pause gate. Preserve shine 0.2.0 whole-frame EncodeBufferInterleaved and upstream Opus/session headers. Preserve partial final real PCM instead of dropping it on EOF. Pause resumes the same reader with rebased pacing. Stop snapshots handles under Streamer.mu and performs cancellation, reader close and waits outside it. One Shutdown combines streamer lifetime, command children, decoder, recovery, output and MPD teardown.

4. Choose B's ten-second internal normal-gap bound. Set one deadline when a real activated track completes or Next skips that active track; a subsequent real track may establish a later gap. Invalid selections, repeated retries and gap output never renew it. Startup, wholly exhausted selection, failures and recovery backoff cannot manufacture indefinite silence. On expiration park output. Pause emits no filler. Real PCM progress alone drives producer health; generated bytes may update availability, never recovery success. Health requests go to the existing playback owner; no second streamFile, decoder or encoder launches. Preserve upstream invalid-playlist retry behavior and cancellable one-to-sixty-second recovery delays.

5. Stream owns playback state and revision; the pump invokes one activation transition after the first real encoded output is successfully published. That transition allocates a new playback ID even when the title repeats, and captures title, existing station-name artist, start time and revision once. History, SSE, track-start hook and on_play_command consume that same snapshot outside stream locks. Reject stale generation activation. No premature CurrentSong assignment or parallel metadata setter remains. Preserve live-source compatibility setters through this owner. Terminal stop/failure/exhaustion/source disappearance explicitly clears title and replay once; pause keeps its current playback identity. Bounded normal gaps do not create new playback events.

6. Keep exactly one instance-lifetime transcode mirror, started before decoder attachment. Subscribe first, reconcile current state immediately, then consume matching input-mount metadata events. Keep the existing five-second broad reconciliation for genre, URL, description, public and visible fields; it must also reconcile playback revision/clear because Relay.NotifyMetadataChange currently drops events when subscriber buffers fill. Resolve the current input on reconciliation after flaps. Mirror source playback ID and start time, but assign output publication revision through the output owner. Reconciliation never republishes unchanged state. Delete both old title-mirror paths. This achieves immediate ordinary propagation and bounded recovery after a dropped event without reinstating a fast poll.

7. Keep existing metadata wire fields mount, title, artist and started_at, including station-name artist and existing timestamp serialization. Add playback_id and revision. B's claim that started_at is optional/new is incorrect: fork relay.MetadataChange and both server SSE serializers already expose it. Both SSE endpoints replay terminal clears and retain current visibility filtering. Ensure older replay or delayed event publication cannot overwrite a newer revision in Relay.lastMeta. Player consumes immediate metadata/clear and rejects older revisions; unversioned periodic stats cannot restore a cleared or older title. Preserve upstream stats/transport/video fields and the intentional existing visibility policy for combined stream events.

8. Listener registry owns atomic admission, actual current mount, destination reservations and outcomes. effective cap = smallest positive of configured MaxListeners and that mount's MaxListeners; zero contributes no bound. The global configuration value is a ceiling applied independently to each mount, not a server-total counter. HTTP and real WebRTC playback share the admission count, internal decoding is excluded, and HLS viewers retain upstream metrics. Pending moves reserve destination capacity while retaining origin ownership; successful subscription then commits transfer. Fail/cancel/disconnect releases reservations. Apply this to fallback and recovery. Reject simultaneous replacement of an already pending move. API reports pending/completed/failed truthfully; unsupported WebRTC move returns 409. Preserve upstream thirty-second fallback hysteresis and ICY state. Persist partial cap/burst updates under config locks; preserve upstream 512-KiB default and 8-MiB clamp.

9. Extend upstream operator UI with retained diagnostics/listeners. Keep numeric AutoDJ state, flat events, playlist_version, numeric IDs, percent volume, is_dir and selected playlist path. Keep upstream authentication/security, browser video restrictions, WHEP/player and packaging fixes. Rebuild all embedded assets together after sources settle. Updater runtime is already absent; remove stale auto_update documentation/spec claims. Existing HotSwap and restart controls are restart mechanisms and remain outside updater removal.

Red-flag review

No actor framework is justified. Do not create wrapper interfaces around the three existing owners. Claim/attachment and move reservation/subscription/commit have necessary transport coordination; keep those calls local to existing producer/listener lifetime boundaries rather than spreading stages across new modules. Delete superseded ownership setters and both mirror loops in the same implementation unit. Avoid separately stored counters or metadata caches that can diverge from the registry/publication owner. Cap policy belongs in one resolver used by every admission and move. A dropped metadata event is a concrete existing behavior, so event-only propagation without reconciliation is insufficient.

Required acceptance evidence

- Actual AutoDJ manager/session against a live preclaimed mount: unchanged headers, byte head, source label and metadata. Repeat competing transport claims and delayed old-generation detach/closer cleanup; verify browser replacement waits for audio and video.
- Persistent MP3 real-tone round trip and requested bitrate; Opus/MP3 joins during a normal gap; partial EOF frame; non-native-rate duration/pitch; no-listener pacing; real Pause/Play without a resume burst.
- Invalid playlist and blocked song_command crossing the gap deadline: no endless filler, no generated health recovery success, retained diagnostics, one producer, and cancellation on stop/delete/shutdown.
- First-frame timing, repeated identical titles with distinct IDs, clear/replay, stale publication rejection, transcode pre-decoder propagation, dropped-event reconciliation and input removal/recreation.
- Concurrent cap admission and destination reservation at boundaries; two mounts may each reach their own configured ceiling; full/disabled fallback leaves truthful current_mount; move failure/cancel/disconnect releases capacity; real WebRTC admission/cleanup; persistence survives reload.
- Compiled embedded operator pages: Studio play/pause/playlist/file/volume, mount partial editing, listener controls, Player replay/clear followed by stats ticks, and browser video smoke. Retain upstream security regression suites and focused race tests, then build and full Go suite.

Blocking design issues are resolved by this synthesis. Implement in existing files with targeted additions; the contracts above are invariants rather than a demand to implement every illustrative candidate type or signature.
